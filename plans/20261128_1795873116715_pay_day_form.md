# Implementation Specification: pay day form

## 1. Objective
Create a full CRUD UI and backend for **pay days** in the Go version of Campbell Checkbook. This includes:
- A form to **add** a new pay day (GET & POST) and **edit** an existing one.
- Corresponding HTML templates that mirror the existing Scala Twirl views.
- Domain models (`PayDay`, `PayDayDeposit`) and repository interfaces with stub implementations.
- Chi route registration (`PayDayRoutes`) integrated with the existing router.
- Unit‑tests for the new handlers.

The implementation must integrate with the existing chi router, Go `html/template` system, and stub DB layer used throughout the project.

### Handler Skeleton (`cmd/handlers/payday.go`)
```go
package handlers

import (
    "context"
    "fmt"
    "html/template"
    "net/http"
    "strconv"

    "github.com/go-chi/chi/v5"
    db "github.com/jlcampbell1991/campbell-checkbook-go/internal/db"
    "github.com/jlcampbell1991/campbell-checkbook-go/internal/domain"
)

type payDayService struct {
    repo        db.PayDayRepository
    depositRepo db.PayDayDepositRepository
    lineItemRepo db.LineItemRepository
    accountRepo db.AccountRepository
    tmpl        *template.Template
}

func PayDayRoutes(t *template.Template, pdRepo db.PayDayRepository, depRepo db.PayDayDepositRepository, liRepo db.LineItemRepository, acctRepo db.AccountRepository) chi.Router {
    s := &payDayService{repo: pdRepo, depositRepo: depRepo, lineItemRepo: liRepo, accountRepo: acctRepo, tmpl: t}
    r := chi.NewRouter()
    r.Get("/", s.index)
    r.Get("/inactive-pay-days", s.inactiveIndex)
    r.Get("/new", s.new)
    r.Post("/", s.create)
    r.Get("/{id}", s.show)
    r.Get("/{id}/edit", s.edit)
    r.Post("/{id}/edit", s.update)
    r.Get("/{id}/deactivate", s.deactivate)
    r.Get("/{id}/reactivate", s.reactivate)
    r.Get("/{id}/get-paid", s.getPaid)
    // deposit sub‑routes omitted for brevity
    return r
}
```
*(Handlers follow the same error‑handling pattern as other services.)*

## 6. Error Handling and Edge Cases
- Missing required fields (`name`, `total`, `account`) → `http.StatusBadRequest` with descriptive message.
- Invalid numeric conversion for `total` or `deposit_amount` → `BadRequest`.
- Repository errors propagate as `500 Internal Server Error`.
- When editing, if the PayDay ID does not exist → `404 Not Found`.
- Deposit list may be empty; the form should still render with zero rows.

## 9. Outstanding Questions and Assumptions
- **Account selection**: The Scala form uses `AccountId` value; we assume the Go `Account` struct exposes `ID` and `Name` fields for the template.
- **LineItem list**: We assume a `LineItem` struct with `ID`, `Name`, and `Balance` exists (it does). The template will need those fields.
- **Deposit amounts**: The Scala form maps `deposit_id` and `deposit_amount`; the Go form will use the same names to keep parity with the backend parsing logic.
- **Authentication**: Existing routes use `ifAuthed`; for this task we assume the same middleware is applied globally, so handlers do not need explicit auth checks.
- **Persistence**: Stub repositories are sufficient for compilation and tests; real DB integration will be added later.
