# Implementation Specification: accounts show

## 1. Objective

Add the **Account "show"** page and its accompanying **delete** endpoint to the Go implementation of *campbell‑checkbook*. The behaviour must match the reference Scala implementation (`AccountsRoutes.scala` and `views/accounts/show.scala.html`).

## 2. Existing Architecture and Relevant Code

| Component | Location | Purpose |
|-----------|----------|---------|
| Server entry point | `main.go` | Starts a `chi` router on `:8080` (hard‑coded). |
| Template embedding | `main.go` (go:embed) | Embeds layout templates from `views/layouts/*.tmpl` and `*.html`. |
| Layout templates | `views/layouts/application.tmpl` & `views/layouts/application.html` | Base HTML page that renders a `{{template "content" .}}` block. |
| Static assets | `static/` (served via chi) | Holds CSS/JS files. |

| No existing domain or DB layer for accounts/transactions – the Go code base currently contains only the home page. |
| No existing handler files – all routes will be added under `cmd/handlers/`. |

**Reference Scala source** (used as the source of truth):
- Backend routes: `/home/jcampbell/node/campbell-checkbook-v2/src/main/scala/jamble/campbell/checkbook/accounts/AccountsRoutes.scala`
- Show view template: `/home/jcampbell/node/campbell-checkbook-v2/src/main/twirl/views/accounts/show.scala.html`

Key behaviours from the Scala code:
1. **Show** (`GET /accounts/{id}?page=n`)
   - Loads the `Account` record.
   - Loads a page of `Transaction` records (`accountService.getTransactions(id, page)`).
   - Loads "dislocated" transactions (`accountService.getDislocated(id)`).
   - Computes `dlTotal` as the net sum of those dislocated transactions (deposits add, withdrawals subtract).
   - Generates a `nextUrl` pointing to the same account with `page+1`.
   - Renders `views.html.accounts.show(account, transactions, dislocateds, dlTotal, nextUrl)`.
2. **Delete** (`GET /accounts/{id}/delete`)
   - Calls `accountService.destroy(id)`.
   - Redirects to the home page (`Redirect("/")`).
3. The **show** template displays:
   - Account name, balance, budget (with CSS class based on withdrawal/deposit).
   - Links for *Edit*, *Delete* (with JS confirm), *New Line Item*.
   - A table of line items (`views.html.accounts.account_items_layout`).
   - A table of transactions (if any) using `views.html.transactions.layout(transactions, nextUrl)`.
   - A table of dislocated transactions (if any) with a link to *Transfer All* that shows the computed `dlTotal`.

## 4. Implementation Plan

1. **Add route registration** in `main.go`:
   - Import the new package (`"campbell-checkbook-go/cmd/handlers"`).
   - After static file handlers, call `r.Mount("/accounts", handlers.AccountRoutes(tmpl))` (or similar). The `tmpl` variable is the parsed `template.Template` from `main.go`.
2. **Create `cmd/handlers/accounts.go`**:
   - Define a function `AccountRoutes(tmpl *template.Template) chi.Router` that returns a router with the two routes.
   - For **show**:
     * Parse optional `page` query param (`r.URL.Query().Get("page")`). Default to `0`.
     * Call repository methods (`Show`, `GetTransactions`, `GetDislocated`).
     * Compute `dlTotal`:
       ```go
       var dlTotal float64
       for _, dl := range dislocated {
           if dl.Category == "Withdrawal" {
               dlTotal -= dl.Amount
           } else { // Deposit
               dlTotal += dl.Amount
           }
       }
       ```
     * Build `nextUrl := fmt.Sprintf("/accounts/%s?page=%d", id, page+1)`.
     * Execute the `show.tmpl` template with a struct containing all needed fields.
   - For **delete**:
     * Call `Destroy(id)`.
     * Issue an HTTP redirect (`http.Redirect(w, r, "/", http.StatusSeeOther)`).
3. **Define domain structs** in `internal/domain` matching the fields used by the view (name, balance, budget, id). Use JSON tags that mirror the Scala case class names (`id`, `name`, `balance`, `budget`).
4. **Add a repository interface** (`internal/db/account_repository.go`). Provide a concrete implementation that uses `pgx` or `database/sql` (the exact DB code can be a stub with `TODO` – the spec only needs to describe the contract). Ensure the signatures accept a `context.Context` and return errors.
5. **Create view templates** (`views/accounts/show.tmpl`, plus any required partials). Translate the Twirl syntax to Go template syntax, preserving the exact HTML structure, CSS class logic, and link URLs.
   - Use a helper function `isWithdrawal` (implemented in a `utils` package) to decide the CSS class for balance/budget.
   - Example snippet for balance row:
     ```go

     </td>
     ```
6. **Update `go.mod`** if new imports are required (e.g., `github.com/google/uuid` for IDs, `github.com/go-chi/chi/v5`).
7. **Run `go vet ./...` and `gofmt -s -w .`** after writing the specification (no code changes yet, but ensure the repo still builds). Verify there are no syntax errors in the existing files.

## 5. Code Samples and Technical Details

### 5.1 Handler skeleton (to be placed in `cmd/handlers/accounts.go`)
```go
package handlers

import (
    "context"
    "fmt"
    "html/template"
    "net/http"
    "strconv"

    "github.com/go-chi/chi/v5"
    "github.com/jcampbell/campbell-checkbook-go/internal/domain"
    "github.com/jcampbell/campbell-checkbook-go/internal/db"
)

type accountService struct {
    repo db.AccountRepository
    tmpl *template.Template
}

func AccountRoutes(t *template.Template, repo db.AccountRepository) chi.Router {
    h := &accountService{repo: repo, tmpl: t}
    r := chi.NewRouter()
    r.Get("/{id}", h.show)
    r.Get("/{id}/delete", h.delete)
    return r
}

func (h *accountService) show(w http.ResponseWriter, r *http.Request) {
    ctx := r.Context()
    id := chi.URLParam(r, "id")
    page, _ := strconv.Atoi(r.URL.Query().Get("page"))
    if page < 0 {
        page = 0
    }
    account, err := h.repo.Show(ctx, id)
    if err != nil {
        http.Error(w, err.Error(), http.StatusNotFound)
        return
    }
    txs, _ := h.repo.GetTransactions(ctx, id, page)
    dislocated, _ := h.repo.GetDislocated(ctx, id)
    var dlTotal float64
    for _, dl := range dislocated {
        if dl.Category == "Withdrawal" {
            dlTotal -= dl.Amount
        } else {
            dlTotal += dl.Amount
        }
    }
    nextURL := fmt.Sprintf("/accounts/%s?page=%d", id, page+1)
    data := struct {
        Account      domain.Account
        Transactions []domain.Transaction
        Dislocated   []domain.Transaction
        DlTotal      float64
        NextURL      string
    }{account, txs, dislocated, dlTotal, nextURL}
    if err := h.tmpl.ExecuteTemplate(w, "accounts_show.tmpl", data); err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
    }
}

func (h *accountService) delete(w http.ResponseWriter, r *http.Request) {
    ctx := r.Context()
    id := chi.URLParam(r, "id")
    if err := h.repo.Destroy(ctx, id); err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
        return
    }
    http.Redirect(w, r, "/", http.StatusSeeOther)
}
```
*(The concrete repository implementation is out of scope for this specification.)*

### 5.3 Helper function `isWithdrawal`
Add a small utility in `utils/currency.go` (or similar):
```go
package utils

func isWithdrawal(amount *float64) bool {
    if amount == nil {
        return false
    }
    return *amount < 0
}
```
Register it with the template set in `main.go` via `tmpl.Funcs(template.FuncMap{"isWithdrawal": utils.isWithdrawal})`.

## 6. Error Handling and Edge Cases
- **Missing account ID** – return `404 Not Found`.
- **Invalid page query** – treat non‑numeric values as `0`.
- **Repository errors** – propagate as `500 Internal Server Error` (or more specific if desired).
- **Delete without confirmation** – the frontend uses `onclick` confirm; backend trusts the request.
- **Empty transaction or dislocated slices** – the template conditionally hides the sections.
- **dlTotal rounding** – format with two decimal places in the template.

## 9. Outstanding Questions and Assumptions
1. **Database schema** – the exact column names/types for `accounts` and `transactions` are not known. The repository interface is defined, but the concrete implementation will need to be written later.
2. **Existing helper templates** – the project currently has no `views/accounts/` or `views/transactions/` directories. The specification assumes they will be created; if the project already contains equivalent templates, adjust the file paths accordingly.
3. **Template function registration** – we assume `main.go` will add any needed functions (`isWithdrawal`) to the template set; if the project already uses a different naming convention, adapt accordingly.
4. **Redirect status code** – Scala uses `Redirect` which defaults to `302`. The Go implementation may use `http.StatusSeeOther (303)`; both are acceptable as long as the client is redirected to `/`.
5. **Authentication** – the Scala routes are wrapped in `ifAuthed`. The Go project currently has no auth middleware; this spec does **not** add authentication, assuming it is out of scope for the current milestone.
