# Implementation Specification: transactions form

## 1. Objective
Create a full CRUD UI and backend for **transactions** in the Go version of Campbell Checkbook. This includes:
- A form to **add** a new transaction (GET & POST).
- (Optional but strongly recommended) edit, delete, toggle‑reconciled, CSV upload/download routes mirroring the existing Scala implementation.
- Corresponding HTML templates.
- Stub repository methods sufficient for compilation and unit‑testing.
- Unit‑tests exercising the new handlers.

The implementation must integrate with the existing chi router, template system, and stub DB layer used throughout the project.

## 2. Existing Architecture and Relevant Code
| Path | Purpose |
|------|---------|
| `cmd/handlers/transactions.go` | Currently only implements `TransactionsIndex` (GET `/transactions`). |
| `internal/domain/transaction.go` | Domain model for a transaction (JSON tags, fields). |
| `internal/db/transaction_repo.go` | Interface `TransactionRepository` with `Index` and `GetAll` stub implementation. |
| `main.go` | Sets up chi router, loads templates (only `views/transactions/*.tmpl` are parsed), registers the `/transactions` list route. |
| `views/transactions/index.tmpl` | List view, contains links for CSV upload/download but no forms. |
| `utils` | Helper `IsWithdrawal` used in templates. |

The project follows the same pattern as `accounts` and `line_items`:
- A **Routes** function (e.g. `AccountRoutes`) returns a `chi.Router` with CRUD endpoints.
- A **Service** struct holds a repository and a parsed `*template.Template`.
- Templates are defined under `views/.../*.tmpl` and executed via `tmpl.ExecuteTemplate`.
- Stub repositories return empty slices or nil errors; they are later replaced with real DB code.

## 4. Implementation Plan
1. **Extend Repository Interface** – add CRUD methods; update stub implementation to satisfy compile.
2. **Create Service & Router** – follow pattern of `AccountRoutes`:
   - `type transactionService struct { repo db.TransactionRepository; tmpl *template.Template }`
   - `func TransactionRoutes(t *template.Template, repo db.TransactionRepository) chi.Router` returns a router with:
     - `r.Get("/", s.index)` – reuse existing `TransactionsIndex` logic (can be moved into the service).
     - `r.Get("/new", s.new)`
     - `r.Post("/", s.create)`
     - (optional) other routes.
3. **Implement Handlers**:
   - `new` parses query params `account_id` and `line_item_id` (if provided) and executes `add.tmpl`.
   - `create` calls `r.ParseForm()`, extracts fields, validates non‑empty `date`, `memo`, numeric `amount`, then builds `domain.Transaction{Date: parsedDate, Memo: memo, Amount: amt, Category: cat, LineItemID: lineItemID, AccountID: accountID}`. Calls `repo.Create` and redirects.
   - Error handling: on parsing/validation errors, `http.Error` with `http.StatusBadRequest`.
4. **Update `main.go`** – replace the single GET route with mounting the new router.
5. **Write Templates** – simple forms using Go template syntax, extending the existing `application.tmpl` layout.
6. **Add Tests** – use `net/http/httptest` to issue requests against the router with the stub repo; assert status codes, redirects, and that stub methods were invoked (can instrument stub with counters or use a mock implementation).
7. **Run Go Tests** – `go test ./...` should pass.
8. **Run Formatter & Vet** – `gofmt -s -w .`, then `go vet ./...`.
9. **Update .gitignore** – add `task-description.md` if not already ignored.

### Create Handler Example
```go
func (s *transactionService) create(w http.ResponseWriter, r *http.Request) {
    if err := r.ParseForm(); err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }
    // parse fields
    dateStr := r.FormValue("date")
    memo := r.FormValue("memo")
    amtStr := r.FormValue("amount")
    cat := r.FormValue("category")
    lineItemID := r.FormValue("line_item_id")
    accountID := r.FormValue("account_id")

    if dateStr == "" || memo == "" || amtStr == "" {
        http.Error(w, "missing required fields", http.StatusBadRequest)
        return
    }
    d, err := time.Parse("2006-01-02", dateStr)
    if err != nil { http.Error(w, "invalid date", http.StatusBadRequest); return }
    amt, err := strconv.ParseFloat(amtStr, 64)
    if err != nil { http.Error(w, "invalid amount", http.StatusBadRequest); return }

    tx := domain.Transaction{Date: d, Memo: memo, Amount: amt, Category: cat, LineItemID: lineItemID, AccountID: accountID}
    if _, err := s.repo.Create(r.Context(), tx); err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
        return
    }
    // redirect to the line‑item view if we have an ID, otherwise home
    redirect := "/"
    if lineItemID != "" {
        redirect = fmt.Sprintf("/line-items/%s", lineItemID)
    }
    http.Redirect(w, r, redirect, http.StatusSeeOther)
}
```

## 6. Error Handling and Edge Cases
- **Missing or malformed form fields** – return `400 Bad Request` with a clear message.
- **Date parsing** – expect `YYYY‑MM‑DD`; if parsing fails, treat as error.
- **Amount conversion** – reject non‑numeric input.
- **Repository errors** – propagate as `500 Internal Server Error`.
- **Redirect logic** – if `line_item_id` is supplied, redirect back to that line‑item page; otherwise fallback to `/`.
- **CSRF** – not in scope for stub implementation.

## 9. Outstanding Questions and Assumptions
- **Routing hierarchy** – the Scala version nests transaction routes under `/accounts/{accountId}/line-items/{lineItemId}`. For simplicity the spec proposes a flat `/transactions` endpoint; if the project later needs the nested structure, the implementing agent can adapt the router accordingly.
- **CSV upload/download** – only the UI placeholders are required; full CSV parsing can be deferred to a later task.
- **Authentication** – the existing project does not enforce auth for other resources, so the new routes will not add auth checks.
- **Database persistence** – stub repository is acceptable for now; real DB integration is out of scope for this task.
