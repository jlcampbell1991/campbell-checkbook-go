# Implementation Specification: transactions show

## 1. Objective
Create a new **/transactions** page in the Go implementation of Campbell Checkbook. The page must list transactions with pagination, provide links for CSV upload/download, and render the table layout that mirrors the existing Scala implementation.

## 2. Existing Architecture and Relevant Code
- **Root server** is defined in `main.go`. It creates a `chi` router, loads configuration, serves static assets, and renders a home page using the `application.tmpl` layout.
- The project already contains a navigation menu (`views/layouts/menu.tmpl`) that includes a link to **/transactions** – the UI expects this route to exist.
- The Scala reference implementation lives outside this repository at:
  - Backend routes: `.../campbell-checkbook-v2/src/main/scala/jamble/campbell/checkbook/transactions/TransactionRoutes.scala`
  - Index view: `.../campbell-checkbook-v2/src/main/twirl/views/transactions/index.scala.html`
  - Table layout: `.../campbell-checkbook-v2/src/main/twirl/views/transactions/layout.scala.html`
- The **AGENTS.md** for this repo lists the intended Go equivalents that are currently missing:
  - `internal/domain/transaction.go`
  - `internal/db/transaction_repo.go`
  - `cmd/handlers/transactions.go`

## 4. Implementation Plan
1. **Add route registration** in `main.go` (modify file). Use `handlers.TransactionsIndex`.
2. **Create domain model** (`internal/domain/transaction.go`). Add imports (`time`). Ensure `go vet` passes.
3. **Create repository stub** (`internal/db/transaction_repo.go`). Provide `Index(page int) ([]domain.Transaction, error)` returning empty slice for now.
4. **Create handler** (`cmd/handlers/transactions.go`). Parse `page` query param (`strconv.Atoi` with default 0). Call repo, build `nextURL`, execute template.
5. **Create view templates** (`views/transactions/layout.tmpl` and `views/transactions/index.tmpl`). Use Go `html/template` syntax; ensure they are parsed by `template.ParseFS` in `main.go` (the existing code parses `views/layouts/*.tmpl` and `*.html`). Add the new files to the embed pattern by updating the `//go:embed` line to include `views/transactions/*.tmpl`. Since the spec restricts us to only modify `task-description.md` and `.gitignore`, we *cannot* edit `main.go` embed line. However the existing embed pattern only includes `views/layouts/*.tmpl` and `*.html`. To load new templates we must either place them under `views/layouts` (not ideal) or rely on the handler to parse templates manually (e.g., `template.ParseFiles`). The specification therefore instructs the implementing agent to load the new templates explicitly inside the handler using `template.ParseFS(templateFS, "views/transactions/*.tmpl")`.
6. **Update .gitignore** to ensure `task-description.md` is ignored.
7. **Run gofmt**, `go vet`, and `go test` (no tests yet, but the checks must be run). Ensure no lint errors.

## 5. Code Samples and Technical Details
- **Parsing page query param**:
```go
pageStr := r.URL.Query().Get("page")
page := 0
if pageStr != "" {
    if p, err := strconv.Atoi(pageStr); err == nil {
        page = p
    }
}
```
- **Building next URL**:
```go
nextURL := fmt.Sprintf("/transactions?page=%d", page+1)
```
- **Template execution**:
```go
tmpl, err := template.ParseFS(templateFS, "views/transactions/*.tmpl")
if err != nil { http.Error(w, err.Error(), http.StatusInternalServerError); return }
data := struct{ Transactions []domain.Transaction; NextURL string }{transactions, nextURL}
if err := tmpl.ExecuteTemplate(w, "application.tmpl", data); err != nil { ... }
```

## 6. Error Handling and Edge Cases
- Invalid `page` query param → treat as `0`.
- Repository errors → return `http.StatusInternalServerError` with generic message.
- Template parsing errors → same as above.
- Empty transaction list → page still renders with empty table and a functional “Next” link (which will loop but is acceptable for stub).

## 8. Acceptance Criteria
- `GET /transactions` returns a 200 HTML page that matches the layout described above.
- Pagination works: query param `page` is respected and `nextUrl` points to the next page.
- Links for **Upload CSV**, **Download CSV**, **Edit**, **Delete**, **Toggle‑reconciled**, and **Relocate** are present in the generated HTML (they may be dead links for now).
- All new Go files compile with `go build`.
- `gofmt -s -w` has been run on every new/modified file.
- `go vet ./...` reports no issues.
- `task-description.md` is present at the repository root and is listed in `.gitignore`.

## 9. Outstanding Questions and Assumptions
1. **Database schema** – The exact columns for the `transactions` table are not verified in this repo. The implementation currently uses a stub repository; the real DB queries will need to be added later.
2. **Template loading** – The existing embed pattern only includes `views/layouts/*.tmpl` and `*.html`. The specification assumes the handler can load additional templates via `template.ParseFS`. If the project prefers embedding all templates, the implementing agent will need to adjust the embed directive (outside the scope of this task).
3. **Currency formatting** – The Scala view uses a custom `Currency.fromDouble`. The Go version uses `fmt.Sprintf("%.2f", amount)`. A more sophisticated helper can be added later.
4. **Category CSS class** – The Scala view uses `TransCat.toString(transaction.category)`. The Go version will output the raw category string as a CSS class; this assumes the CSS definitions exist.
5. **Reconcile toggling** – The toggle‑reconciled link includes a query param `reconciled`. The handler for that endpoint is not required for this task.
