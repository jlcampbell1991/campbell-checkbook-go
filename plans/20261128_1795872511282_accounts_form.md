# Implementation Specification: accounts form

## 1. Objective
Create a user‑interface and backend endpoints to **add a new account**.

* Render a form at `GET /accounts/new`.
* Accept the form submission at `POST /accounts` and create the account via the existing `AccountRepository`.
* After a successful creation, redirect the user to the home page (`/`).
* Add the corresponding Go HTML template.

## 2. Existing Architecture and Relevant Code
| Component | Path | Notes |
|-----------|------|-------|
| Account domain model | `internal/domain/account.go` | `type Account struct { ID string; Name string; Balance float64; Budget float64 }` |
| Account repository interface | `internal/db/account_repository.go` | Provides `Insert(ctx context.Context, a domain.Account) (string, error)` for persisting a new account. |

## 3. Required Changes
### 3.1 Files to Modify
1. **`cmd/handlers/accounts.go`**
   * **Add two routes** to the router:
     ```go
     r.Get("/new", h.new)
     r.Post("/", h.create)
     ```
   * **Implement handler methods**:
     * `func (h *accountService) new(w http.ResponseWriter, r *http.Request)` – renders the new‑account form using the template `accounts_add.tmpl`.
     * `func (h *accountService) create(w http.ResponseWriter, r *http.Request)` –
       * Parse the posted form (`r.ParseForm()`), read the `name` field.
       * Build a `domain.Account{ Name: name }` (ID can be empty – the repository is responsible for generating it).
       * Call `h.repo.Insert(r.Context(), acc)`. On error, respond with `http.StatusInternalServerError`.
       * On success, `http.Redirect(w, r, "/", http.StatusSeeOther)`.
   * **Add required imports**: `net/http` is already present; we need to import `github.com/jlcampbell1991/campbell-checkbook-go/internal/domain` (already imported) – no new imports needed.
2. **`cmd/handlers/accounts.go`** – update the comment header of `AccountRoutes` to reflect the new endpoints.

### 3.2 Files to Create
1. **`views/accounts/add.tmpl`** (template for the new‑account form)
   ```gotemplate
   {{define "accounts_add.tmpl"}}
   {{template "application.tmpl" .}}
   {{define "content"}}
   <h2>New Account</h2>
   <form action="/accounts" method="post">
       Name: <input type="text" name="name" required><br>
       <input type="submit" value="Create Account">
   </form>
   {{end}}
   {{end}}
   ```
   * The template follows the same pattern as `accounts/show.tmpl` – it uses the shared `application.tmpl` layout.
   * No data struct is required; the handler can pass an empty struct (`struct{}{}`) or `nil`.

## 4. Implementation Plan
1. Open `cmd/handlers/accounts.go` and add the two route registrations **before** the existing `r.Get("/{id}", h.show)` line to keep more specific routes later.
2. Implement the `new` method: execute `h.tmpl.ExecuteTemplate(w, "accounts_add.tmpl", struct{}{})` and handle the error with `http.StatusInternalServerError`.
3. Implement the `create` method:

   * Build `acc := domain.Account{Name: name}`.
   * Call `_, err := h.repo.Insert(r.Context(), acc)`; on error return 500.
   * Redirect to `/` with status `http.StatusSeeOther`.
4. Create the new template file `views/accounts/add.tmpl` with the content shown above.
5. Run `go test ./...` (currently there are only stub tests for DB; they should still pass).
6. Run `gofmt -s -w .` and `go vet ./...` to satisfy the Go conventions.
7. Verify that the application compiles (`go build ./...`).

## 5. Code Samples and Technical Details
* **Route registration snippet** (to be inserted in `AccountRoutes`):
  ```go
  r.Get("/new", h.new)   // render the form
  r.Post("/", h.create)  // handle submission
  ```
* **`new` handler**:
  ```go
  func (h *accountService) new(w http.ResponseWriter, r *http.Request) {
      if err := h.tmpl.ExecuteTemplate(w, "accounts_add.tmpl", struct{}{}); err != nil {
          http.Error(w, err.Error(), http.StatusInternalServerError)
      }
  }
  ```
* **`create` handler**:
  ```go
  func (h *accountService) create(w http.ResponseWriter, r *http.Request) {
      if err := r.ParseForm(); err != nil {
          http.Error(w, err.Error(), http.StatusBadRequest)
          return
      }
      name := r.FormValue("name")
      if name == "" {
          http.Error(w, "name is required", http.StatusBadRequest)
          return
      }
      acc := domain.Account{Name: name}
      if _, err := h.repo.Insert(r.Context(), acc); err != nil {
          http.Error(w, err.Error(), http.StatusInternalServerError)
          return
      }
      http.Redirect(w, r, "/", http.StatusSeeOther)
  }
  ```
* **Template file** – see section 3.2.

## 6. Error Handling and Edge Cases
* **Form parsing failure** – return `400 Bad Request`.
* **Missing `name` field** – return `400 Bad Request` with a clear message.
* **Repository insertion error** – return `500 Internal Server Error`.
* **Template execution error** – return `500 Internal Server Error`.
* All redirects use `http.StatusSeeOther` (303) to follow the pattern used elsewhere.

## 7. Testing Requirements

  * Status code `200`.
  * Response body contains `<form` and the `action="/accounts"` attribute.
* **Unit test for `create` handler** – send a POST request with form data `name=TestAccount` and assert:

  * Response status is `303` and `Location` header is `/`.
  * When the `name` field is missing, the handler returns `400`.
* Existing tests for other handlers should continue to pass.

## 9. Outstanding Questions and Assumptions
1. **ID generation** – The repository implementation (currently a stub) returns the ID supplied in the struct. We assume a real implementation will generate a UUID or DB‑generated ID, so the handler does not need to create one.
2. **Redirect target after creation** – Scala code redirects to the home page (`/`). We follow the same behaviour.
3. **Template data** – No additional data (e.g., title) is required for the form; an empty struct is sufficient.
4. **Authentication/authorization** – Existing routes are not protected; the new routes follow the same pattern (no auth checks).
5. **Styling** – The form uses the existing layout and default CSS; no custom styling is mandated.
