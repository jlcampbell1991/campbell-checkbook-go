# Implementation Specification: line-items form

## 1. Objective
Create a user‑interface and backend for adding a new **Line Item**. The form should be reachable at `/accounts/{accountId}/line-items/new` and submit via POST to `/accounts/{accountId}/line-items`. The implementation must mirror the Scala reference (`add.scala.html` and `LineItemsRoutes.scala`) while conforming to the existing Go codebase conventions.

## 2. Existing Architecture and Relevant Code
| Component | Path | Role |
|-----------|------|------|
| Domain model | `internal/domain/line_item.go` | `type LineItem struct { ID, AccountID, Name string; Balance float64 }` |
| Repository interface | `internal/db/line_item_repository.go` | Provides `Show`, `GetTransactions`, `GetPayDayDeposits` (stub implementation only). |
| Show handler & routes | `cmd/handlers/line_items.go` & `main.go` (mounted at `/line-items`) | Renders `line_items_show.tmpl`.
| Templates parsed at startup | `main.go` – parses `views/layouts/*.tmpl`, `views/layouts/*.html`, `views/transactions/*.tmpl` |
| Existing show template | `views/line_items/show.tmpl` | Uses `application.tmpl` layout.
| Stub repository | `internal/db/line_item_repository.go` | In‑memory placeholders, no insert capability.

The project follows the chi router, html/template rendering, and stub repositories pattern used for accounts and transactions.

## 3. Required Changes

### 3.1 Files to Modify
1. **`main.go`**
   - Extend the template parsing call to include `views/line_items/*.tmpl` so the new form template is available.
   - Register two new routes **before** the generic `/line-items` mount:
     ```go
     r.Get("/accounts/{id}/line-items/new", func(w http.ResponseWriter, r *http.Request) { ... })
     r.Post("/accounts/{id}/line-items", func(w http.ResponseWriter, r *http.Request) { ... })
     ```
   - The handlers must:
     * Extract `id` via `chi.URLParam`.
     * For **GET**: render `line_items_form.tmpl` with a data struct containing `AccountID` (string) and `Title` ("New Line Item").
     * For **POST**: parse form fields `name`, `balance`, `accountId`; construct a `domain.LineItem`; call `lineItemRepo.Insert`; on success redirect to `/accounts/{accountId}` using `http.StatusSeeOther`.
   - Add `fmt` import if not already present for `Redirect` URL formatting.
2. **`internal/db/line_item_repository.go`**
   - Extend the `LineItemRepository` interface with:
     ```go
     Insert(ctx context.Context, li domain.LineItem) (string, error)
     ```
   - Implement the method on `StubLineItemRepo` to simply return `li.ID` (or generate a placeholder ID) and `nil` error.
   - Update the stub file to import `github.com/google/uuid` (or use any deterministic placeholder) if you decide to generate an ID; otherwise, rely on the caller to set `ID`.
3. **`cmd/handlers/line_items.go`** (optional but recommended)
   - Add a compile‑time check that the repository now satisfies the extended interface (no code change required if only the interface is referenced).
   - No functional changes needed; the file already imports the repository interface.

## 4. Implementation Plan
1. **Template parsing** – modify `main.go`'s `template.ParseFS` call to include `views/line_items/*.tmpl`.
2. **Repository interface** – add `Insert` method; update stub implementation.
3. **Create form template** – add `views/line_items/form.tmpl` with the markup above.
4. **Route handlers** – implement inline handlers in `main.go`:
   * **GET** handler builds a data struct `{Title:"New Line Item", Action: fmt.Sprintf("/accounts/%s/line-items", id), Method:"post", AccountID:id}` and executes `line_items_form.tmpl`.
   * **POST** handler reads form values via `r.ParseForm()`, converts `balance` to `float64` (`strconv.ParseFloat`), constructs `domain.LineItem{AccountID: accountId, Name: name, Balance: bal}` and calls `lineItemRepo.Insert`. On error, return `http.StatusInternalServerError`; otherwise redirect.
5. **Import additions** – add `fmt`, `strconv`, `github.com/jlcampbell1991/campbell-checkbook-go/internal/domain` to `main.go` imports.
6. **Run `go vet` / `go test`** – there are currently no tests for line items; ensure the code compiles.
7. **Formatting** – run `gofmt` (the harness will do it automatically).

```go
func (s *StubLineItemRepo) Insert(ctx context.Context, li domain.LineItem) (string, error) {
    // In a real implementation an ID would be generated by the DB.
    // For the stub we simply return the provided ID or a placeholder.

        li.ID = "stub-id"
    }
    return li.ID, nil

```
### GET Handler Example
```go
r.Get("/accounts/{id}/line-items/new", func(w http.ResponseWriter, r *http.Request) {
    id := chi.URLParam(r, "id")
    data := struct {
        Title     string
        Action    string
        Method    string
        AccountID string
    }{
        Title:     "New Line Item",
        Action:    fmt.Sprintf("/accounts/%s/line-items", id),
        Method:    "post",
        AccountID: id,
    }
    if err := tmpl.ExecuteTemplate(w, "line_items_form.tmpl", data); err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
    }
})
```
### POST Handler Example
```go
r.Post("/accounts/{id}/line-items", func(w http.ResponseWriter, r *http.Request) {
    if err := r.ParseForm(); err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }
    name := r.FormValue("name")
    balStr := r.FormValue("balance")
    acct := r.FormValue("accountId")
    bal, _ := strconv.ParseFloat(balStr, 64)
    li := domain.LineItem{Name: name, Balance: bal, AccountID: acct}
    if _, err := lineItemRepo.Insert(r.Context(), li); err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
        return
    }
    http.Redirect(w, r, fmt.Sprintf("/accounts/%s", acct), http.StatusSeeOther)
})
```

## 6. Error Handling and Edge Cases
- **Missing form fields** – `ParseForm` will return empty strings; treat empty `name` or invalid `balance` as a `400 Bad Request`.
- **Balance conversion failure** – if `strconv.ParseFloat` returns an error, respond with `400`.
- **Repository insertion error** – return `500 Internal Server Error`.
- **Redirect** – always use `http.StatusSeeOther` (303) to follow POST‑Redirect‑GET pattern.

4. **Negative tests** – missing `name` or non‑numeric `balance` should result in `400`.
5. **Template compilation test** – ensure `template.ParseFS` does not error after adding the new pattern.

Update any existing test files that import `LineItemRepository` to satisfy the new interface (they will need a mock that implements `Insert`). If no tests currently reference the interface, only add the new tests.

## 9. Outstanding Questions and Assumptions
1. **ID generation** – The stub repository does not generate a UUID. We assume the caller (or future real DB layer) will provide an ID. For the stub we return a placeholder (`"stub-id"`).
2. **Form validation** – Minimal validation is required (non‑empty name, numeric balance). More sophisticated validation can be added later.
3. **Template naming** – Chosen `line_items_form.tmpl` to match existing naming convention (`line_items_show.tmpl`). If the project prefers a different suffix, adjust accordingly.
4. **Redirect target** – After creation we redirect to the account show page (`/accounts/{accountId}`). This mirrors the Scala route which redirects to `"/accounts/${id}"`.
5. **No existing tests for line‑item creation** – New tests will be added; they assume the stub repository is sufficient for compilation.
