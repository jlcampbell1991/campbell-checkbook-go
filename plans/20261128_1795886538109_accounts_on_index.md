Outstanding Questions and Assumptions<br>- **SQL implementation**: The exact query for `AccountRepository.Index` is not provided; we assume it will be implemented later based on the Scala query.<br>- **Line‑item fields**: The Scala model includes fields `budget` and `balance` as `Option[Double]`. We map these to `*float64` in Go. If the database stores them as nullable numeric columns, the scan logic must handle nulls.<br>- **Currency helper**: The Scala `Currency.isWithdrawal` returns a CSS class name based on sign. We assume a simple implementation that returns "withdrawal" for negative values and "deposit" otherwise.<br>- **Template naming**: Go's `html/template` expects defined template names; we use `application.tmpl` as the base and define `accounts_index` and `account_items_layout` within the same file set.<br>- **Routing base path**: The Scala version serves the index at `/` (root). We keep the same behaviour; additional account‑specific pages (`/accounts/{id}`) are out of scope for this task.<br>- **Dependency injection**: The handler receives a repository and the compiled template set; this matches the existing pattern in `main.go` where templates are parsed once.</p>
