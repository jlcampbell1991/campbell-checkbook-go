# Implementation Specification: line-items show

## 1. Objective

Add the **Line‑Item "show"** page and its supporting HTTP endpoint to the Go implementation of *campbell‑checkbook*. The behaviour must match the reference Scala implementation (`LineItemsRoutes.scala` and `views/line_items/show.scala.html`). The endpoint should render a server‑side HTML page displaying a line item, its associated pay‑day deposits, and a paginated list of transactions.

- Backend routes: `/home/jcampbell/node/campbell-checkbook-v2/src/main/scala/jamble/campbell/checkbook/line_items/LineItemsRoutes.scala`
- Show view template: `/home/jcampbell/node/campbell-checkbook-v2/src/main/twirl/views/line_items/show.scala.html`

Key behaviours from the Scala code (lines 55‑66):
1. **GET /line-items/{id}?page=n**
   - `id` is a `LineItemId`.
   - Optional `page` query parameter defaults to `0`.
   - Retrieves the `LineItem` record via `LineItemRepository.show(id)`.
   - Retrieves a page of `Transaction` records via `LineItemRepository.getTransactions(lineItem.id, page)`.
   - Retrieves all `PayDayDeposit` records linked to the line item via `PayDayDepositRepository.getAllByLineItem(LineItemId(id))`.
   - Constructs `nextUrl = "/line-items/{id}?page={page+1}"`.
   - Returns HTML rendering `views.html.line_items.show(lineItem, deps, transactions, nextUrl)`.

The Twirl view (`show.scala.html`) renders:
- Header with the line‑item name.
- A resource‑menu table with **Edit**, **Delete** (with JS confirm), **Account** link, **Balance** (styled by withdrawal/deposit), and shortcuts to add a transaction, transfer, or pay‑day deposit.
- Conditional inclusion of a pay‑day‑deposit layout (`views.html.pay_days.layout(deps)`).
- Conditional inclusion of a transaction table (`views.html.transactions.layout(transactions, nextUrl)`).

## 5. Code Samples and Technical Details

### 5.1 Handler skeleton (`cmd/handlers/line_items.go`)
```go
package handlers

import (
    "context"
    "fmt"
    "html/template"
    "net/http"
    "strconv"

    "github.com/go-chi/chi/v5"
    "github.com/jcampbell/campbell-checkbook-go/internal/domain"
    db "github.com/jcampbell/campbell-checkbook-go/internal/db"
)

type lineItemService struct {
    repo db.LineItemRepository
    tmpl *template.Template
}

func LineItemRoutes(t *template.Template, repo db.LineItemRepository) chi.Router {
    s := &lineItemService{repo: repo, tmpl: t}
    r := chi.NewRouter()
    r.Get("/{id}", s.show)
    return r
}

func (s *lineItemService) show(w http.ResponseWriter, r *http.Request) {
    ctx := r.Context()
    id := chi.URLParam(r, "id")
    page, _ := strconv.Atoi(r.URL.Query().Get("page"))
    if page < 0 { page = 0 }

    li, err := s.repo.Show(ctx, id)
    if err != nil {
        http.Error(w, err.Error(), http.StatusNotFound)
        return
    }
    txs, _ := s.repo.GetTransactions(ctx, id, page)
    deps, _ := s.repo.GetPayDayDeposits(ctx, id)
    nextURL := fmt.Sprintf("/line-items/%s?page=%d", id, page+1)

    data := struct {
        LineItem    domain.LineItem
        Deps        []domain.PayDayDeposit
        Transactions []domain.Transaction
        NextURL     string
    }{li, deps, txs, nextURL}

    if err := s.tmpl.ExecuteTemplate(w, "line_items_show.tmpl", data); err != nil {
        http.Error(w, err.Error(), http.StatusInternalServerError)
    }
}
```

## 6. Error Handling and Edge Cases

- Invalid or missing `id` → return **404 Not Found**.
- `page` query param not an integer → treat as `0`.
- Repository methods may return an error; propagate as **500 Internal Server Error** (or **404** if the line item is not found).
- Empty `deps` or `transactions` slices → the conditional blocks simply omit the corresponding tables (as in the Scala view).
- Ensure that the generated `nextUrl` always increments the page number even when there are no further records; pagination UI can later hide the link if the next page is empty.
