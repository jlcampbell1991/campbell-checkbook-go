## Project Overview
This repository implements the **Campbell Checkbook** backend in Go, providing a REST API and server‑side rendered HTML templates for managing accounts, transactions, transfers, pay‑days, line items, and reconciliation. It mirrors the functionality of the original Scala version.

## Repository Layout
| Path | Purpose |
|------|---------|
| `main.go` | Application entry point; sets up the chi router, in‑memory repo, and starts the HTTP server on `:8080`. |
| `cmd/handlers/` | HTTP handler registrations and helper functions (e.g., `accounts.go`). |
| `internal/domain/` | Domain model structs with JSON tags (e.g., `account.go`). |
| `internal/db/` | Repository interfaces and in‑memory implementations (`account_repo.go`). Also contains migration utilities (`migrate.go`, `buildpostgresurl.go`). |
| `views/` | `html/template` files for server‑side rendering (e.g., `accounts/form.tmpl`). |
| `static/` | Static assets served by chi’s file server (`css/`, `javascript/`). |
| `Makefile` | Simple dev shortcut (`make run`). |
| `README.md` | Systemd service setup instructions. |
| `start.sh` | Script used by the systemd service to launch the binary. |

## Development Commands
- **Run locally**: `make run` (executes `go run main.go`).
- **Run tests**: `go test ./...` – executes all unit and integration tests, including handler tests.
- **Static analysis**: `go vet ./...`.
- **Formatting**: `gofmt -s -w .` – must be run before committing (project enforces gofmt). 
- **Database migrations**: `go run internal/db/migrate.go <DSN>` or invoke `RunMigrations` programmatically; migrations live in `internal/db/migrations/`.

## Testing Strategy
- Unit tests are located alongside the code they exercise (e.g., `cmd/handlers/accounts_test.go`).
- Handler tests use `net/http/httptest` and chi router to verify HTTP responses.
- Repository tests (if added) should use the in‑memory repo or a temporary PostgreSQL instance.
- CI runs `go test ./...`, `go vet`, and `gofmt -l` to enforce quality.

## Build & Deployment
- **Systemd service** – see `README.md` for the service unit template. The service runs `start.sh`, which launches the compiled binary.
- **Binary** – build with `go build -o campbell-checkbook`.
- **Environment** – configuration is loaded from a `.env` file via `github.com/joho/godotenv` (not yet present; add as needed). Typical variables: `POSTGRES_URL`.

## Coding Conventions (enforced)
- All Go files must pass `gofmt -s -w .` before committing.
- Run `go vet ./...` and address any warnings.
- Follow the folder layout shown above; new packages should live under `internal/` or `cmd/` as appropriate.
- Use explicit `json` struct tags matching the API contract.
- Errors returned to HTTP clients should be surfaced with appropriate status codes (e.g., `http.StatusBadRequest`).

## Known Limitations & TODOs
